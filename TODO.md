# Техническое задание: версия сайта AST для слабовидящих

Целевой уровень: АА по ГОСТ Р 52872-2019.

## 1. Переключение версии

1. В шапке основной версии добавить текстовую ссылку/кнопку «Версия для слабовидящих».
2. Элемент должен быть доступен с клавиатуры: Tab → Enter/Space.
3. В доступной версии добавить «Обычная версия сайта».
4. Доступная версия должна содержать те же тексты, разделы, карточки, формы, ссылки и функции, что основная.
5. Контент обеих версий должен обновляться одновременно.
6. Настройку доступной версии сохранять при переходах между страницами.

Основание: определение соответствующей альтернативной версии и раздел 5 ГОСТ Р 52872-2019.

## 2. Контраст и отображение

### Текст

- обычный текст: контраст с фоном не менее 4,5:1;
- крупный текст: не менее 3:1;
- текст не размещать на фотографии, если невозможно обеспечить необходимый контраст;
- заголовки, цены, названия курсов, кнопки и подписи должны быть HTML-текстом, а не частью изображения.

ГОСТ: 1.4.3, 1.4.5 — уровень АА.

### Элементы интерфейса

Границы, управляющие иконки и другие визуальные элементы, необходимые для использования интерфейса, должны иметь контраст не менее 3:1 относительно соседнего фона.

ГОСТ: 1.4.11 — уровень АА.

### Цвет

Нельзя передавать информацию только цветом.

Например, ошибка формы должна отображаться не только красным цветом, но и текстовым сообщением.

ГОСТ: 1.4.1 — уровень A.

## 3. Масштабирование и адаптив

1. Текст должен увеличиваться до 200% без:
   - обрезания текста;
   - наложения блоков;
   - исчезновения кнопок;
   - потери функций.
2. Не использовать фиксированные высоты блоков, если при увеличении текста они приводят к обрезке содержимого.
3. При ширине области просмотра 320 CSS px страница должна перестраиваться без горизонтальной прокрутки всей страницы.
4. Карточки курсов, новостей, материалов, отзывов и другие многоколоночные блоки на малой ширине перестраиваются в одну колонку.

ГОСТ: 1.4.4 и 1.4.10 — уровень АА.

## 4. Интервалы текста

Страница не должна ломаться при пользовательской установке:

- line-height: 1.5;
- расстояния между абзацами: 2 размера шрифта;
- letter-spacing: 0.12em;
- word-spacing: 0.16em.

Не задавать размеры и высоты блоков так, чтобы изменение этих параметров обрезало содержимое.

ГОСТ: 1.4.12 — уровень АА.

## 5. Клавиатурное управление

Весь функционал сайта должен работать без мыши.

Обязательна работа с клавиатуры для:

- меню;
- выпадающих меню;
- ссылок;
- кнопок;
- карточек;
- слайдеров;
- формы;
- модальных окон;
- поиска;
- переключателя версии сайта.

### Tab-порядок

Tab должен перемещать фокус в логическом порядке, соответствующем расположению контента.

Не использовать положительный tabindex.

ГОСТ: 2.1.1 и 2.4.3 — уровень A.

### Клавиатурные ловушки

Пользователь должен иметь возможность клавиатурой войти в любой компонент и выйти из него.

ГОСТ: 2.1.2 — уровень A.

### Видимый фокус

Каждый интерактивный элемент должен иметь заметное состояние focus.

Не удалять outline, если вместо него не реализован равноценный визуальный индикатор.

ГОСТ: 2.4.7 — уровень АА.

### Пропуск меню

Перед основной навигацией добавить скрытую до получения фокуса ссылку:

«Перейти к основному содержанию»

Она должна переводить фокус непосредственно в `<main>`.

ГОСТ: 2.4.1 — уровень A.

## 6. HTML-структура и скринридеры

Использовать семантическую структуру:

```
header
nav
main
section
footer
```

Заголовки оформлять через H1–H6 в логической последовательности.

На странице должен быть один основной H1.

У каждой страницы должен быть осмысленный и уникальный `<title>`.

Для русскоязычных страниц:

```
<html lang="ru">
```

Использовать стандартные HTML-элементы:

- `<button>` для действий;
- `<a>` для переходов;
- `<input>`, `<textarea>`, `<select>` для форм.

Не делать интерактивные элементы обычным `<div onclick>` без соответствующей роли и клавиатурной логики.

Все элементы интерфейса должны иметь программно определяемые название, роль, состояние и значение.

ГОСТ: 1.3.1, 2.4.2, 2.4.6, 3.1.1, 4.1.2.

## 7. Изображения и иконки

### Значимые изображения

Добавить содержательный alt.

Пример:

```
alt="Группа слушателей на занятии по дегустации вина"
```

### Декоративные изображения

Использовать:

```
alt=""
```

и не передавать их скринридеру как содержательный элемент.

### Иконки

Иконки поиска, профиля, соцсетей, переключения слайдов и другие функциональные иконки должны иметь доступное название.

Например:

```
aria-label="Поиск"
aria-label="Следующий слайд"
```

ГОСТ: 1.1.1 и 4.1.2 — уровень A.

## 8. Слайдеры, карусели и анимация

На текущей главной AST:

- hero «История виноделия»;
- «Полезные материалы»;
- «Новости»;
- «Отзывы»

в доступной версии работают без автоматической прокрутки.

Оставить ручное переключение.

Стрелки реализовать как `<button>` с доступными названиями:

- «Предыдущий слайд»;
- «Следующий слайд».

Если где-либо на сайте автоматически движущийся/прокручиваемый контент работает более 5 секунд, пользователь должен иметь возможность поставить его на паузу, остановить или скрыть.

Не допускать вспышек чаще трёх раз в секунду.

ГОСТ: 2.2.2 и 2.3.1 — уровень A.

## 9. Изменения конкретно на главной AST

### Шапка

- добавить «Версия для слабовидящих»;
- сделать все пункты меню клавиатурными;
- дать текстовые accessibility-названия иконкам;
- обеспечить видимый focus.

### Hero «История виноделия»

- отключить автопрокрутку;
- текст и CTA оставить HTML-текстом;
- стрелки сделать доступными кнопками;
- если текст расположен поверх изображения и не проходит контраст — вынести его на однотонный фон.

### «Добро пожаловать в Школу вина AST»

- сохранить корректную структуру заголовков и текста;
- декоративные изображения скрыть от скринридера;
- блок не должен ломаться при увеличении текста до 200%.

### «Ближайшие курсы»

Название, формат, описание, цена и CTA — HTML-текст.

Каждая карточка:

- имеет понятную ссылку/кнопку;
- доступна с клавиатуры;
- имеет focus-state;
- при увеличении и на малой ширине перестраивается без обрезания текста.

### «Рекомендуем вам»

Текст и кнопки не должны быть частью изображения.

### «Полезные материалы», «Новости», «Отзывы»

- отключить автопрокрутку;
- ручные стрелки сделать `<button>`;
- обеспечить работу с клавиатуры;
- при малой ширине не создавать горизонтальную прокрутку всей страницы.

### Рейтинг

Не передавать рейтинг только звёздами.

Добавить доступный текст:

«4,9 из 5»

Декоративные звёзды скрыть от скринридера.

## 10. Форма «Остались вопросы?»

У каждого поля должен быть постоянный `<label>`.

Placeholder не использовать как единственную подпись.

Для полей использовать корректные типы и autocomplete:

- имя;
- e-mail;
- телефон.

Если поле заполнено неправильно:

1. визуально обозначить поле;
2. вывести текст ошибки;
3. программно связать ошибку с полем.

Пример:

«Введите корректный e-mail»

После отправки формы сообщения:

- «Заявка отправлена»;
- «Ошибка отправки»;

должны быть доступны скринридеру через `role="status"`, `role="alert"` или aria-live в зависимости от ситуации.

ГОСТ: 1.3.5, 3.3.1–3.3.3, 4.1.3.

## 11. Футер

- все ссылки должны иметь понятное назначение;
- телефон и e-mail должны оставаться текстом;
- соцсети должны иметь доступные текстовые названия;
- не оставлять функциональные иконки без accessibility-label.

## 12. Приёмка

Работа считается выполненной после проверки:

1. Весь сайт можно пройти только клавиатурой.
2. Focus всегда виден.
3. Клавиатурных ловушек нет.
4. При увеличении текста до 200% ничего не обрезается и функции не пропадают.
5. При ширине 320 CSS px нет горизонтальной прокрутки всей страницы.
6. Контраст:
   - обычный текст ≥ 4,5:1;
   - крупный текст ≥ 3:1;
   - необходимые элементы интерфейса ≥ 3:1.
7. Все значимые изображения имеют alt.
8. Декоративные изображения не озвучиваются скринридером.
9. Все кнопки, ссылки и функциональные иконки имеют доступное имя.
10. Порядок H1–H6 логичен.
11. Tab-порядок соответствует визуальному порядку.
12. Автопрокрутка в доступной версии отключена либо имеет механизм остановки.
13. Формы полностью работают с клавиатуры.
14. Ошибки и результат отправки формы доступны скринридеру.
15. Страница проверена на desktop и mobile.
16. Выполнена проверка минимум со скринридером VoiceOver либо NVDA.

Если заявляется соответствие всего сайта уровню АА, проверяется не только главная страница, а все публичные страницы и все шаги пользовательских процессов.

## 13. Не включать в обязательный объём как «требование ГОСТ AA»

ГОСТ Р 52872-2019 не требует:

- обязательного набора цветовых схем «белый / чёрный / синий / жёлтый»;
- строго заданного минимального размера шрифта, например 18 px;
- обязательного размера кнопки 44×44 px для уровня AA — этот критерий в данном ГОСТ относится к уровню AAA;
- отдельного дублирующего сайта, если основной интерфейс уже соответствует требованиям.

Для проекта AST доступная версия реализуется как альтернативный режим сайта по требованию проекта.
