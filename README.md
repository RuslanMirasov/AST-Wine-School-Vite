# AST - Школа вина

Статическая вёрстка на Vite, без фреймворков. HTML собирается из переиспользуемых кусков (`<load>`), стили — из SCSS, вся логика — обычный ванильный
JS без сборки в один бандл (в `dist` модули лежат такими же отдельными файлами, как и в исходниках — удобно передавать вёрстку дальше, например под
интеграцию в Bitrix).

## Быстрый старт

```bash
npm install
npm run dev       # разработка, localhost:5173
npm run build     # сборка в dist/
npm run preview   # предпросмотр собранного dist/
```

## Валидация форм (JS)

Валидация подключена один раз глобально (`initForms()` в `scripts.js`) и работает автоматически для всех форм на странице, у которых стоят атрибуты
`data-form` и `novalidate` — вызывать вручную ничего не нужно, достаточно правильно разметить HTML.

### Быстрый старт

```html
<form data-form novalidate>
  <label class="label">
    <span class="label-text">Email</span>
    <input type="email" name="email" class="input" required />
  </label>

  <button type="submit" class="button">Отправить</button>
</form>
```

Главное правило: **валидация цепляется за атрибут `data-form`**. `novalidate` обязателен на каждой форме — он глушит нативный попап браузера, но не
мешает нашей валидации (она использует тот же браузерный API, просто рисует ошибки сама).

### Как поле получает правило проверки

Приоритет (сверху вниз, первое найденное — используется):

1. `pattern="..."` — свой regex прямо в разметке, ничего в JS трогать не нужно
2. `data-rule="имя"` — ссылка на готовое именованное правило
3. `type` / `inputmode` — правило по умолчанию для типовых полей
4. просто `required`, без проверки формата

```html
<!-- 1. Свой формат прямо в разметке -->
<input type="text" pattern="^[A-Z]{2}\d{4}$" title="Формат: AB1234" required />

<!-- 2. Готовое правило по имени -->
<input type="text" data-rule="email" required />

<!-- 3. Правило само подхватится по type, ничего указывать не нужно -->
<input type="email" required />
```

Готовые именованные правила (`assets/js/forms/validationRules.js`):

| `data-rule`     | Срабатывает само по   | Формат                                                |
| --------------- | --------------------- | ----------------------------------------------------- |
| `email`         | `type="email"`        | `name@domain.ru`                                      |
| `tel`           | `type="tel"`          | `+7 999 000 00 00`                                    |
| `decimal`       | `inputmode="decimal"` | `100` или `100.50`                                    |
| `name`          | —                     | буквы любого алфавита и дефис (`Петров-Водкин`)       |
| `name-cyrillic` | —                     | только кириллица и дефис                              |
| `code`          | —                     | ровно N цифр, где N = `data-code="N"` на этом же поле |

### Нативная валидация — бесплатно, без единой строчки JS

`required`, `minlength`/`maxlength`, `min`/`max`, `step` обрабатываются автоматически через встроенный браузерный `validity` API — просто ставьте
атрибут:

```html
<input type="text" minlength="2" maxlength="30" required /> <input type="number" min="18" max="99" required />
```

### Два способа вывести ошибки

По умолчанию ошибка появляется под каждым полем. Чтобы вместо этого собрать все ошибки формы в один блок снизу — добавьте его в разметку **внутри
самой формы**, `<form data-form novalidate>`:

```html
<div class="form-errors" data-form-errors></div>
```

Режим переключается автоматически по наличию этого блока внутри формы.

### Свой текст ошибки

`data-error-text="..."` переопределяет сообщение поля. Приоритет зависит от того, есть ли у поля `data-rule` (или `type`/`inputmode`-fallback):

- **Нет `data-rule`** — `data-error-text` перебивает **любую нативную ошибку** (`required`, `minlength`, `pattern` и т.п.), какая бы из них ни
  сработала.
- **Есть `data-rule`** — `data-error-text` перебивает **только ошибку самого правила** (когда значение заполнено, но не проходит `rule.test`).
  Нативные ошибки (например, пустое обязательное поле) при этом показываются как обычно, из словаря в `validationRules.js` — `data-error-text` их не
  трогает, т.к. относится к формату значения, а не к его отсутствию.

```html
<!-- нет data-rule — перебивает и required, и любую другую нативную ошибку -->
<input type="checkbox" required data-error-text="Согласие на обработку данных обязательно" />

<!-- есть data-rule — перебивает только ошибку формата; пустое поле покажет обычное "Это обязательное поле!" -->
<input type="tel" data-rule="tel" required data-error-text="Укажите номер в формате +7 999 000 00 00" />
```

`title="..."` по-прежнему используется как текст ошибки для `pattern` без `data-rule`, если `data-error-text` не задан (стандартный смысл атрибута
`title` для `pattern` в HTML).

### Свой текст ошибки в общем блоке ошибок

В общем блоке (`[data-form-errors]`) ошибка обычно выглядит как `«текст лейбла»: сообщение`, где текст лейбла берётся из `.label-text`/`legend`. Если
у поля задан `data-error-text` и именно он оказался итоговым сообщением (см. приоритет выше) — в общем блоке он выводится **целиком, как готовая
строка**, без склейки с `«label-text»:`. Так удобнее для длинных лейблов (чекбоксы согласия) или когда формулировка `«title»: message` не подходит.

```html
<div class="form-errors" data-form-errors></div>

<label class="label">
  <input type="checkbox" required data-error-text="Согласие на обработку данных обязательно" />
  <p class="label-text">
    <span>Согласен с <a href="/policy/">Условиями обработки персональных данных</a></span>
  </p>
</label>
```

В общем блоке появится ровно `Согласие на обработку данных обязательно`, без префикса.

Если же у поля есть `data-rule`, `data-error-text` задан, но сработала **нативная** ошибка (например, поле пустое) — сообщение в этом случае не равно
`data-error-text`, и в общем блоке используется обычный формат `«label-text»: message`.

### Radio-группы

Всегда оборачивайте группу в `<fieldset>` с `<legend>` — это не только семантика: `<legend>` используется как заголовок ошибки в общем блоке ошибок, а
сам `<fieldset>` — как место, куда крепится **одна** ошибка на всю группу (а не на каждый `radio` отдельно).

```html
<fieldset class="row">
  <legend class="label-text">Ваш пол</legend>
  <label class="label"><input type="radio" name="sex" required /> Мужчина</label>
  <label class="label"><input type="radio" name="sex" required /> Женщина</label>
</fieldset>
```

### Select / Choices.js

Работает без дополнительных настроек. Если у `<select>` есть родитель с классом `.choices` (так библиотека оборачивает поле) — класс ошибки `.invalid`
автоматически продублируется на эту обёртку, т.к. сам `<select>` Choices прячет визуально.

### Полное отключение вывода ошибок

`SHOW_ERRORS` в `assets/js/forms/errorRenderer.js` — общий флаг на все формы сайта. При `false` поля всё ещё помечаются `.invalid` (рамка красная), но
текст ошибки нигде не показывается — ни под полем, ни в общем блоке.

### Для интеграции в Bitrix (или любую другую CMS)

Форма и её валидация полностью работают на клиенте и ничего сами не отправляют — модуль только блокирует `submit`, если форма невалидна
(`event.preventDefault()`); если всё заполнено верно, событие `submit` идёт дальше как обычно, так что серверный экшен/компонент вешается на форму как
всегда, без оглядки на этот модуль.

При переносе вёрстки в компоненты обязательно сохранить:

- атрибут `data-form` на `<form>` и `novalidate`
- обёртку `<label>` вокруг поля (используется, чтобы найти место под текст ошибки)
- `.label-text` / `<legend>` — видимый текст, который подставляется в заголовок ошибки в общем блоке ошибок
- атрибут `name` у полей — запасной вариант заголовка, если видимого текста лейбла нет
- `<div data-form-errors></div>`, если в форме используется общий блок ошибок

#### Ошибка, отрисованная сервером, вручную в разметке

Если ошибка уже известна на сервере (например, Bitrix при повторном рендере страницы после невалидной отправки) — её можно вставить прямо в HTML, без
единой строчки JS. JS сам находит такую разметку и не создаёт дубликат:

```html
<label class="label">
  <span class="label-text">Email</span>
  <input type="email" name="email" class="input invalid" value="test@test.ru" />
  <span class="inputError active" role="alert">Такой email уже зарегистрирован</span>
</label>
```

- `.invalid` — на самом поле.
- `.inputError.active` — **прямым потомком того же `<label>`**, сразу после поля. Класс `active` форсирует показ (`display`/`height`) через
  `!important`, минуя анимацию — ошибка видна сразу же, без JS.
- По фокусу на поле ошибка уберётся штатно, как и любая другая — `.active` тоже корректно снимается (`animateHeight.js` учитывает его при
  схлопывании).
- Это работает, только если поле — **единственный** `input`/`select`/`textarea` внутри своего `<label>`. Если в одном `<label>` несколько полей (см.
  пример с кодом подтверждения ниже) — JS не пытается угадать, какому из них принадлежит существующий `.inputError`, и создаёт свой отдельно на каждое
  поле через `getErrorElement`.

### OTP-код (несколько полей, одна ошибка)

`assets/js/forms/inputCode.js` — паттерн для кода подтверждения из нескольких квадратов, которые физически отдельные `input`, но должны давать
**одну** ошибку на всех:

```html
<label class="label label-code">
  <input type="number" name="code" data-code="4" data-rule="code" required tabindex="-1" aria-hidden="true" />
</label>
```

- Само поле `[data-code]` — агрегирующее и скрытое (не участвует в отправке визуально, но именно оно валидируется правилом `code`).
- `initCodeInputs()` генерирует `N` (значение `data-code`) видимых `input[type=number]`-боксов рядом с ним — без `name`, чтобы они не попадали в
  `FormData` при реальной отправке.
- Ввод в любом боксе синхронизирует агрегирующее поле и переносит фокус на следующий пустой; Backspace на пустом — на предыдущий.
- Именно поэтому для полей внутри `.label-code` не работает автоопределение существующего `.inputError` из раздела выше — в одном `<label>` пять полей
  (агрегирующее + 4 бокса), и JS не может понять, кому из них принадлежит ошибка в разметке.

### Структура модуля

`assets/js/forms/`

| Файл                      | За что отвечает                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| `validationRules.js`      | словарь нативных сообщений + именованные кастомные правила (email/tel/decimal/name/code/...) |
| `resolveRules.js`         | резолвинг кастомного правила для поля: `data-rule` → `type` → `inputmode`                    |
| `resolveAnchor.js`        | группировка radio по `name` и поиск общего предка для ошибки группы                          |
| `validateField.js`        | проверка одного поля: нативный `validity` → кастомное правило, приоритет `data-error-text`   |
| `validateForm.js`         | обход всех полей формы, маркировка `.invalid`, сбор ошибок                                   |
| `errorRenderer.js`        | базовый контракт стратегий вывода + флаг `SHOW_ERRORS`                                       |
| `inlineErrorRenderer.js`  | вывод ошибки под полем (режим по умолчанию), учитывает готовую разметку с `.active`          |
| `summaryErrorRenderer.js` | вывод всех ошибок одним блоком в `[data-form-errors]`                                        |
| `animateHeight.js`        | анимация раскрытия/схлопывания блоков с ошибками, снятие `.active` при схлопывании           |
| `factory.js`              | выбор inline/summary-рендерера по наличию `[data-form-errors]` в форме                       |
| `inputCode.js`            | генерация полей OTP-кода и их синхронизация с агрегирующим `[data-code]`                     |
| `index.js`                | точка входа — `initForms()`, обработчики фокуса/change/submit                                |

### Как добавить новое кастомное правило

Например, нужна проверка ИНН. Добавляем правило в `validationRules.js`:

```js
export const customRules = {
  // ...существующие
  inn: {
    test: value => /^\d{10}(\d{2})?$/.test(value.trim()),
    message: 'ИНН должен содержать 10 или 12 цифр',
  },
};
```

И используем в разметке — без изменений где-либо ещё в JS:

```html
<input type="text" data-rule="inn" required />
```
